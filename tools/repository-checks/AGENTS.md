# @template/repository-checks

## このパッケージが守るもの

このリポジトリの検査（リポジトリを走査して問題を報告する CLI）が、読み取り・問題の形・終了コードについて 1 つの契約を共有している状態。

同じ契約の宣言が 2 箇所にあると、片方だけが直されたときに何も落ちない。両者が食い違うのは実行時であり、そのとき失敗するのは変更した側ではない。このパッケージは、検査の契約の宣言をここが所有することで、2 箇所目が生まれない状態を保つ。

## 何を置くか

- IF: 宣言が検査の契約（読み取り・問題の形・終了コード）に属し、2 つ以上のパッケージが取り込む; THEN MUST: ここへ置き、双方が取り込む
- IF: 1 行の式で書ける処理を共有したくなった; THEN
  - PROHIBIT: 関数としてここへ置く
  - MUST: 呼び出し箇所に式として書く
- IF: 宣言が検査の契約に属さない; THEN
  - PROHIBIT: ここへ置く
    - 契約の外の宣言を受け入れた時点で、このパッケージは所有者の決まっていない残余に戻る
  - MUST: それを所有する領域を名前にした置き場所を使う
- IF: 1 つのパッケージしか使っていない; THEN
  - PROHIBIT: ここへ置く
    - 使う場所から離れた位置に宣言が置かれ、読む側は宣言と使用箇所を往復することになる
  - MUST: 使う側に置く
- IF: 同じ処理がユーティリティライブラリで提供されている; THEN
  - MUST: そちらを使う
  - PROHIBIT: ここへ包み直したものを置く

## 規範文書の在り処

どのファイルが規範文書なのかは、検査ごとに決めると食い違う。ここが 1 つの読み手を持ち、リポジトリのマニフェストの `normativeDocuments` を正本にする。`fileName` は場所ごとの規約を読む先の名前で、`directories` はその直下の Markdown を規範文書として扱う置き場である。置き場はリポジトリの直下と各ワークスペースの下の両方で探し、直下だけを見て、リンクは辿らない。

- IF: 規範文書かどうかを判定したい; THEN
  - MUST: ここが返す一覧を使う
  - PROHIBIT: 置き場のパスや文書の名前を検査の側に書く
- IF: マニフェストが宣言を持たない; THEN
  - MUST: 置き場が無いものとして扱う
  - PROHIBIT: 既定の置き場を仮定する
    - このパッケージは外部の利用者に配られる。既定を置くと、宣言していないリポジトリに置き場を作る要求が届く

## 公開面

- IF: ここから何かを公開する; THEN MUST: 実際に取り込まれていることを確かめる
  - 誰も使っていない公開面は、未使用の検出が報告する
