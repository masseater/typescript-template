---
title: 秘密と権限
description: 秘密の値が残る場所と、実行に与える権限の幅についての判断基準
---

この文書が守るのは 2 つある。秘密の値が、置いた場所の外に残らないこと。実行に許すことの幅が、宣言の側から読めること。前者が要るのは、値がリポジトリの内容と履歴に残り、実行が出す内容にも混ざるからである。後者が要るのは、資格情報が外へ出たときの被害の上限を決めるのが、事故そのものではなく平時に敷いてある設定だからである。

どちらも、起きた後に打てる手が無い。平文で一度出た値について、複写が何部できたかを数える手段は無い。効く操作は、出す前にしか無い。

このリポジトリで秘密が動く場所は 3 つある。開発者の手元、Cloudflare Workers の実行環境、Google Secret Manager である。手元の開発用の値は dotenvx で暗号化して `apps/<app>/.dev.vars` に置き、復号鍵は鍵ごとに 1 つの Secret へ分けている。本番の実行環境が読む値は Worker の secret binding が持ち、Alchemy が外部サービスへ繋ぐためのトークンは Secret Manager にある。ここで見るのは、その実行に何を持たせるかだけである。

## 秘密の値を平文でこのリポジトリに置かない

秘密として扱うのは、それを持っていること自体が「誰かとして振る舞ってよい」根拠になる値である。鍵でもトークンでも署名の材料でも、受け取る側が本人性の証拠として使うなら同じに扱う。接続先のアカウントを名指しする識別子も分けない。その識別子だけで通ってしまうかどうかを決めるのは繋ぎ先の実装で、こちら側には安全な方へ分類する材料が無い。

- MUST: 資格情報にあたる値は、実行を起こした側から実行時に渡ってくる形にする
- PROHIBIT: 秘密の値を、平文のままこのリポジトリが追跡するファイルへ書き込む
  - ファイルの種類では分けない。一度コミットに入れば、いま見えている内容から消しても履歴から読める
- IF: 開発用の値をリポジトリに置く必要がある; THEN
  - MUST: dotenvx で暗号化した `apps/<app>/.dev.vars` に置く
  - MUST: 復号鍵を scope ごとに 1 つの Secret へ分ける
  - PROHIBIT: 複数の scope の復号鍵を 1 つのファイルや 1 つの Secret にまとめる
- IF: どこから資格情報を取るかを設定として書き留めたい; THEN
  - MUST: 書き留める対象を、保管先の指し方だけに留める
  - PROHIBIT: 値の実体をそこへ置く
- IF: 資格情報の形をした値を、文書やテストの中に書く必要がある; THEN MUST: そのままでは何の相手にも通らないと読み取れる値を選ぶ

平文の環境変数ファイルがコミットに入ることは `.vite-hooks/pre-commit` が見ている。この判定が黙っている状態は、そこに置かれた値の性質については何も言っていない。

## 見つかった値を無効にして取り除く

秘密の値を網羅的に探す仕組みは、このリポジトリにまだ無い。`.vite-hooks/pre-commit` が見ているのは、名前に `env` を含むファイルが暗号化されているかどうかだけである。誤って挙がった値の扱いを決めた項目が効き始めるのは、探す仕組みを入れた時点である。

- IF: 本物の資格情報がこのリポジトリに平文で入っていたと分かった; THEN MUST: その値を使えなくしたうえで、いまの内容からも公開済みの履歴からも取り除く
  - 片方だけで済ませると、使える鍵か、読める記述のどちらかが残る
- PROHIBIT: 広い範囲を除外に指定して、探す仕組みを黙らせる
  - 指定した範囲は将来書かれる値にも効き続けるので、広く取るほど探す仕組みが見ない領域が残る
- IF: 探す仕組みが挙げた値が秘密でない; THEN MAY: その根拠を同じ変更に添えたうえで、挙がったその 1 件だけを対象から外す

## 出力に秘密を通さない

このリポジトリの出力は、標準出力と標準エラー、HTTP の応答、Sentry へ送るイベントとログとトレース、`alchemy plan` が PR へ書くコメントである。最後の 1 つは公開される場所へ出るため、宣言に秘密の値が現れる形を作らない。

- PROHIBIT: 秘密の値そのものを出力に載せる
- PROHIBIT: 個人を名指しできる値を出力へ流す
  - 診断を厚くしたいという要求は、この一線の外側で満たす
- IF: 値の存在や形だけを出力に残したい; THEN MUST: 元へ復元できない形にしたものを出す
- IF: Alchemy の宣言で秘密の値を扱う; THEN
  - MUST: secret として宣言し、preview の差分に平文が現れない形にする
  - PROHIBIT: 値そのものを宣言の入力として書く
- IF: 出力の手前で機微な値を取り除く層を持ち込む; THEN
  - MUST: 何を取り除くかの定義を 1 つに保ち、どの出力先へ届く前にも必ずそこを経由させる
  - MUST: 機微な内容を運ぶキーを増やすときは、その同じ変更で定義の側にも載せる
  - PROHIBIT: 出力先が増えるたびに、そこへ取り除く処理を書き足す
- IF: 中身をキーで分けられない塊を出力へ流したい; THEN MUST: 塊そのものではなく、量や種別のような外形だけを出す

## 読み出せる主体を、読んでよい主体に一致させる

保管先を分けても、その保管先を読める主体が広ければ守れていない。読める主体の集合が、読んでよい主体の集合と一致していることまでを確かめる。

- IF: 秘密の値の置き場所を選ぶ; THEN
  - MUST: その置き場所から値を読み出せる主体をすべて数え上げる
  - PROHIBIT: 置き場所を分けたことだけを根拠に、読める範囲が狭まったとみなす
    - Worker の `secret_text` binding は API から値を返さない。`plain_text` は Workers Scripts を読める主体なら誰でも読める
- IF: 継承によって広い権限を持つ主体が、読んでよい主体に含まれていない; THEN
  - MUST: 明示的な拒否でその主体を止める
  - MUST: 拒否の例外に入れるのを、読んでよい主体だけに限る
  - MUST: 拒否が実際に効いていることを、例外に入っている主体の資格情報で確かめる
    - 確かめるまでは、例外の側も効いているかどうかが分かっていない状態である
- IF: 秘密の値の読み取りを記録する必要がある; THEN MUST: その保管先の読み取りの監査ログを有効にする
- IF: 値を読み出せない主体だけがその値を知っている; THEN
  - MUST: その値を宣言の管理下に入れない
  - MUST: 値を入れる主体と手順を、その領域を所有する文書に書く

## 実行が持つ権限を宣言に限る

ここで言う実行は、CI で走る検査と適用、Cloudflare Workers が動かすアプリ、手元で起動するコマンドである。どれも、何ができるかを宣言の側で決め、実行の側で足せないようにする。

- MUST: 実行の単位ごとに、その実行が要る権限だけを宣言する
- PROHIBIT: 実行基盤が既定で渡してくる権限をそのまま受け取る
  - 何も宣言していない状態が意味するのは、権限を確かめた結果ではなく、確かめていないことである
- PROHIBIT: 検査が通らないことを理由に、宣言する権限を広げる
- IF: 外部サービスへ機械が接続する必要がある; THEN
  - MUST: API トークンを持たずに済む方法を先に探す
  - MUST: 探す順序を、OIDC による federation、サービスが提供する短命の資格情報、鍵なしの連携機構の順にする
  - MUST: 判断を、記憶ではなく公式のドキュメントと実際の API の応答で確かめる
  - IF: どの方法も提供されていないことを確認した; THEN
    - MAY: API トークンを使う
    - MUST: そのトークンを Secret Manager に置き、CI には OIDC で得た権限から読ませる
  - PROHIBIT: 長期のトークンを最初の選択肢にする
  - PROHIBIT: トークンをリポジトリ・ワークフローの定義・環境変数ファイルに置く
- IF: 承認や隔離を迂回する仕組み、あるいは通常の経路では持たない能力を実行へ与える仕組みを用意する; THEN
  - MUST: 既定を無効とし、起動の時点で確かめられる明示の指定があるときだけ有効にする
  - PROHIBIT: その能力を常時有効な形で埋め込む

## 変更を起こす口は、その地点で判定する

- IF: 変更を起こす口を新しく開く、あるいは既にある口の受け口を広げる; THEN
  - MUST: 変更が実際に起きる地点で、どの対象へ何をしようとしているのかを確かめる
  - PROHIBIT: 判定は呼び出す側で済んでいるものとして省く
    - 呼び出す側に置いた判定が覆うのは、それを書いた時点で存在していた経路だけで、後から加わる経路がそこを通る保証は無い
- IF: 誰として要求したのかを確かめる仕組みを持ち込む; THEN PROHIBIT: そこを通過した事実だけで変更を認める
- IF: 判定が正しいことを機械で確かめられない経路が残る; THEN MUST: そこを人が読んで確かめる側へ回す
- IF: 保護された環境を、資格情報を持たない主体に開ける必要がある; THEN
  - MUST: 保護そのものは残し、迂回する経路を主体ごとに分けて発行する
  - PROHIBIT: 保護を外して代わりにする

## 検査を通っていないコードの手が届く範囲

CI が取り出すのはリビジョン 1 つで、それはまだこちらの検査を通っていないコードである。動き始めた瞬間に、その実行の手元にあるものを読める。

- IF: 取り出したリビジョンが動く場所に資格情報を置く必要がある; THEN
  - MUST: 取り出す操作が、そのとき使った資格情報を作業ツリーに残さない設定であることを確かめる
  - MUST: 置くものを、用途を絞ったうえで、選べる期限のうち最も短いものに限る
  - MUST: その資格情報を作る処理を、取り出したコードが動く場所の外で走らせる
  - PROHIBIT: 期限の長い鍵を、取り出したコードの手が届く場所に残す
- IF: 差分を取るために、もう 1 つのリビジョンを並べて取り出す; THEN MUST: 並べたそれぞれを、こちらの検査を通っていないコードとして扱う
- IF: 実行の途中で起動する処理に認証が要る; THEN
  - MUST: どの資格情報を使うかを、その処理の呼び出しに書いて渡す
  - PROHIBIT: 実行の周囲に残っているログイン済みの状態をあてにする

## 資格情報は目的ごとに分ける

- IF: 外にあるサービスへ繋ぐ自動化を足す; THEN
  - MUST: その処理が触る対象と、行う操作の範囲に収まる資格情報を使う
  - MUST: 期限は、選べる選択肢のうち最も短いものにする
- PROHIBIT: 相手が通してしまうことを理由に、発行した目的の外へ資格情報を回す
  - Alchemy が管理 API を呼ぶためのキーと、アプリが機能のために使うキーは、同じサービスのものでも別に発行する
- IF: 1 つの資格情報を複数の実行単位で共有しようとしている; THEN
  - MUST: 失効させたときに止まる範囲を数え上げる
  - PROHIBIT: 失効の影響が数え上げられないまま共有する
- IF: 人ではなく自動化がこのリポジトリを書き換える; THEN
  - MUST: その自動化のために発行した資格情報を使う
  - PROHIBIT: 個人に紐づく資格情報を、自動化の定常的な手段として使う
    - 発行者が組織を離れると失効する種類のトークンは、この条件を満たさない
