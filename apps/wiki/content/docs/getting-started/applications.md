---
title: アプリの役割
description: 3 つのアプリが誰のために何をするか、どのデータに触れるか
---

アプリは、使う人の側で 2 つに分かれる。サービスの一部として会員と運用担当が使うものと、サービスを運営する会社の中の人が使うもの。アカウントも使う人ごとに別々で、同じ人が 2 つの立場を持つなら、アカウントを 2 つ持つ。

## 会員向けアプリ（`apps/user`）

- 使う人は会員。会員でない訪問者に見せるのは LP だけで、ほかの会員のプロフィールは会員にしか見せない
- 会員が自分のプロフィールを作り、ほかの会員を知り、やり取りするための場所
- 会員の AI エージェントや外部のシステムも、会員が許した範囲で、その会員として使う
- 触れるデータは、自分のデータと、ほかの会員が公開したプロフィールまで
- 運用のための操作は持たない

## 管理画面（`apps/admin`）

- 使う人はサービスの運用担当。社外の業務委託の人の場合もある
- 会員の状況を調べ、問い合わせに答え、会員への処置を行うための場所
- 会員とサービスのデータを書き換えるのは、アプリの中ではここだけ
- 会員どうしの会話の中身は見せない
- 集計の閲覧と機能フラグの切り替えは持たない。どちらも社内向けのダッシュボードにある

## 社内向けのダッシュボード（`apps/wiki`）

- 使う人は、サービスを運営する会社の中の人。事業の側とサービスの運用の側の両方
- サービスの状況を知るための場所。開発と運用の文書・集計・監査ログを読み、AI エージェントにも MCP で文書を配る
- 開発の文書も含めて、文書はすべてここに置く。文書だけを別のアプリに分けない
- 読むための場所で、書き込むのは機能フラグと、このダッシュボードを使える人の管理だけ
- 個人を特定できる情報は出さない。問い合わせのように、会員 ID で個別に引く必要があるものだけを例外にする
- いまあるのは、文書と、文書を配る MCP だけ

## 誰が何に触れるか

| アプリ                   | 読める                                         | 書ける                               |
| ------------------------ | ---------------------------------------------- | ------------------------------------ |
| 会員向けアプリ           | 自分のデータ、ほかの会員が公開したプロフィール | 自分のデータ                         |
| 管理画面                 | 会員のデータ（会話の中身を除く）               | 会員のデータ、管理者の追加           |
| 社内向けのダッシュボード | 集計、監査ログ、文書、問い合わせ               | 機能フラグ、ダッシュボードを使える人 |

いまは 3 つのアプリが同じ DB に直接つながり、会員と管理者が 1 つのアカウントの表を共有しているので、この境界はまだ成り立っていない。[#268](https://github.com/masseater/typescript-template/issues/268) から [#273](https://github.com/masseater/typescript-template/issues/273) で、DB を持つ裏方を 1 つにまとめ、アカウントを分けてから成り立つ。
