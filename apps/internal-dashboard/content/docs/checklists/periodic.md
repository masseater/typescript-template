---
title: 定期的に見るとき
description: 週、月、四半期、年の区切りで見るものと、見た結果を書く場所
---

- 始めるきっかけ: 週、月、四半期、年の区切りが来たとき
- 終わる条件: 見た結果、動くと決めたものが issue になっている

## 毎週

- milestone の進み具合と遅れている節目を見ます。
- 障害とアラートの件数、SLO の誤り予算の減り方を見ます。見方は [SLI と SLO](/observability/sli-slo) にあります。
- 答えていない問い合わせを [問い合わせの一覧](/pages/admin-inquiries) で見ます。

## 毎月

- 予算と実績の差を見ます。[Cloudflare](https://www.cloudflare.com/) の費用は予算監視が月の予算と比べます。それ以外の外部サービスは請求書で見ます。予算を変えたら [サービスの定義](/decisions/service#予算) と GitHub Environment の secret を同じ日に直します。
- 品質の定義で決めた指標の推移を見て、次にやることを決めます。
- 溜まっている依存の更新の PR を片付けます。PR は [Renovate](https://docs.renovatebot.com/) が `renovate.json` の設定で作ります。

## 四半期

- リスク用のラベルを付けた issue を見直し、閉じるものと足すものを整理します。
- 関係者と警告の宛先を見直します。書く場所: [サービスの定義](/decisions/service#決める人と関係者) と GitHub Environment の secret
- 管理アカウントと権限を棚卸しし、抜けた人の権限を外します。書く場所: [運用の決めごと](/decisions/operations#権限)
- 契約している外部サービスを棚卸しします。書く場所: [事業の決めごと](/decisions/business#ドメインとアカウント)

## 毎年

- 利用規約とプライバシーポリシーを法令の改正と今のサービスに照らして見直します。変えるときは [管理者アプリの規約](/pages/admin-terms) で新しい版を公開します。
- 品質の定義と変更の審査の手順が今の体制に合っているかを見直します。書く場所: [サービスの定義](/decisions/service)
- 年ごとの契約の更新と翌年の予算を決めます。ドメインと届出の更新の期限もここで見ます。書く場所: [事業の決めごと](/decisions/business)
