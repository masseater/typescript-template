description: 事業の案が出てから畳むまで、場面ごとに決めることと見ることを並べる
---

事業を進める場面ごとに、決めることと見ることを並べます。開発は段階ではなく「作っているとき」の中の作業として扱い、事業や運用や広報と同じ並びに置きます。

骨組みは [PMBOK ガイド第 8 版](https://www.pmi.org/standards/pmbok) に合わせています。節は Focus Area（活動の種類）を場面に読み替えたもので、各節の小見出しは Performance Domain（並行して動く分野）です。

## 節

| 節 | 始めるきっかけ | Focus Area |
| --- | --- | --- |
| [案が出たとき](/checklists/idea) | 事業の案を人に話し、検討に時間を使い始めた | Initiating |
| [やると決めたとき](/checklists/commit) | 予算か人を割くと決めた | Planning |
| [作っているとき](/checklists/build) | やると決めたときの終わる条件を満たした | Executing |
| [リリースするとき](/checklists/release) | 公開日を決めた | Closing と次の Initiating |
| [変更や問題が起きたとき](/checklists/change) | 計画にない依頼、障害、想定外の出来事が起きた | Monitoring and Controlling |
| [定期的に見るとき](/checklists/periodic) | 週、月、四半期、年の区切りが来た | Monitoring and Controlling |
| [畳むとき](/checklists/wind-down) | サービスか機能を終わらせると決めた | Closing |

リリースは一度では終わりません。機能を足すたびに「やると決めたとき」から「リリースするとき」までを回し、そのあいだずっと「変更や問題が起きたとき」と「定期的に見るとき」が並走します。

## 分野

各節の小見出しは次の 7 分野です。その場面で動かない分野は省きます。

| 分野 | Performance Domain | 扱うもの |
| --- | --- | --- |
| 統制 | Governance | 決め方、決めたことの記録、品質の定義、変更の審査 |
| 範囲 | Scope | 作るものと作らないもの、受け入れの条件 |
| 日程 | Schedule | 節目と期限 |
| 資金 | Finance | 費用の見積もり、予算、実績 |
| 関係者 | Stakeholders | 利用者、出資者、協力者、告知先、連絡先 |
| 資源 | Resources | 人、外注、外部サービスとそのアカウント |
| リスク | Risk | 脅威と機会、その対応と担当 |

## 項目の書き方

各ページの冒頭に、始めるきっかけと終わる条件を置きます。各項目は、何をするかと、成果物をどこに残すかを書きます。手順はここに書かず、手順を持つ文書へリンクします。

参考: [PMBOK 第 8 版の 7 つの Performance Domain と 40 の process](https://mypreppilot.com/pmp/learn/pmbok-8th-edition-performance-domains)
