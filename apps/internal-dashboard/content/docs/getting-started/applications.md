---
title: アプリの役割
description: 各アプリが誰のために何をするか、どのデータに触れるか
---

この文書が書いているのは、決まった役割と境界である。各アプリでいま使える機能は、ページ構成の節にある画面の仕様が持つ。画面が前提にする概念と関係は [データモデル](/data-model/overview) が持つ。

アプリは、使う人の側で 2 つに分かれる。サービスの一部として利用者と運用担当が使うものと、サービスを運営する会社の社内の人が使うもの。アカウントは、利用者・運用担当・社内の人でそれぞれ別に持ち、同じ人が複数の立場を持つなら、アカウントも複数持つ。

## 利用者アプリ（`apps/service-member`）

- 使う人は、会員として登録した利用者。登録していない訪問者に見せるのは LP だけで、ほかの利用者のプロフィールは、ログインした利用者にしか見せない
- 利用者が自分のプロフィールを作り、ほかの利用者を知り、やり取りするための場所
- 利用者の AI エージェントや外部のシステムも、利用者が許した範囲で、その利用者として使う
- 運用のための操作は持たない

## 管理者アプリ（`apps/service-admin`）

- 使う人はサービスの運用担当。社外の業務委託の人の場合もある
- 利用者の状況を調べ、問い合わせに答え、利用者への処置を行うための場所
- ほかの利用者のデータを書き換えられるのは、ここだけ。管理者の追加もここで行う
- 利用者同士の会話の中身は見せない
- 集計の閲覧と機能フラグの切り替えは持たない。どちらも wiki が持つ

## wiki（`apps/internal-dashboard`）

- 社内ダッシュボードとして、社内の人が使う。事業の側と、サービスの運用の側の両方
- サービスの状況を知るための場所。開発と運用の文書・集計・監査ログを読み、AI エージェントにも MCP で文書を配る
- 文書は、開発向けも運用向けもここで配る。文書を配るためだけの別のアプリは作らない
- 読むための場所で、書き込むのは機能フラグと、wiki を使える人の管理だけ。問い合わせも読むだけで、答えるのは管理者アプリ
- 個人を特定できる情報は出さない。問い合わせのように、利用者 ID で個別に引く必要があるものだけを例外にする
- いまあるのは、文書と、文書を配る MCP だけ

## 誰が何に触れるか

| アプリ       | 読める                                           | 書ける                       |
| ------------ | ------------------------------------------------ | ---------------------------- |
| 利用者アプリ | 自分のデータ、ほかの利用者が公開したプロフィール | 自分のデータ                 |
| 管理者アプリ | 利用者のデータ（会話の中身を除く）               | 利用者のデータ、管理者の追加 |
| wiki         | 集計、監査ログ、文書、問い合わせ                 | 機能フラグ、wiki を使える人  |
