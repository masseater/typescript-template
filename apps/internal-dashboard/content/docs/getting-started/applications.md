---
title: アプリの役割
description: 各アプリが誰のために何をするか、どのデータに触れるか
---

この文書が定めるのは、テンプレートに含まれる各アプリケーションの役割と境界です。各アプリで現在使える機能は、ページ構成の節にある画面の仕様が持ち、画面が前提にする概念と関係は [データモデル](/data-model/overview) が持ちます。

アプリは、利用者の立場に応じて明確に分離されています。サービスの一部として利用者と運用担当が使うもの、サービスを運営する会社の社内の人が使うもの、そして手元の開発を支援するものに分かれます。アカウントは、利用者・運用担当・社内の人でそれぞれ別に持ち、同じ人が複数の立場を持つ場合はアカウントも複数持ちます。

## 利用者アプリ（`apps/service-member`）

- 使う人は、会員として登録した利用者です。登録していない訪問者に見せるのは LP だけで、ほかの利用者のプロフィールはログインした利用者にしか見せません。
- 利用者が自分のプロフィールを作り、ほかの利用者を知り、やり取りするための場所です。
- 利用者の AI エージェントや外部のシステムも、利用者が許した範囲で、その利用者として使います。
- 運用のための操作は一切持ちません。

## 管理者アプリ（`apps/service-admin`）

- 使う人はサービスの運用担当者です。社外の業務委託の人の場合もあります。
- 利用者の状況を調べ、問い合わせに答え、問題のある利用者への処置を行うための場所です。
- ほかの利用者のデータを直接更新できるのは、ここだけです。管理者の追加もここで行います。
- 利用者同士のプライベートな会話の中身は見せません。
- 全体集計の閲覧や機能フラグの切り替えは持たず、wiki が担います。

## wiki（`apps/internal-dashboard`）

- 社内ダッシュボードとして、事業側と運用側の双方が使います。
- サービスの状況を知るための場所です。開発と運用の文書・集計・監査ログを閲覧し、AI エージェントにも MCP で文書を配布します。
- 文書は開発向けも運用向けもここで配り、文書配布のためだけの別アプリは作りません。
- 読むための場所であり、書き込みは機能フラグの操作と wiki 利用者の管理に限られます。
- 個人を特定できる情報は原則として出さず、問い合わせのように利用者 ID で個別に引く必要があるものだけを例外とします。

## 司令塔アプリ（`tools/commander`）

- 開発者が手元で起動し、AI エージェントと協調してタスクを進めるためのツールです。
- 自然言語でタスクを依頼し、Beads（`bd`）のタスク管理と連携して作業エージェントへタスクを委譲します。
- タスクの一覧とコメントのやりとりを同一画面で監視・指示できます。

## 誰が何に触れるか

| アプリ       | 読める                                           | 書ける                                   |
| ------------ | ------------------------------------------------ | ---------------------------------------- |
| 利用者アプリ | 自分のデータ、ほかの利用者が公開したプロフィール | 自分のデータ                             |
| 管理者アプリ | 利用者のデータ（会話の中身を除く）               | 利用者のデータ、管理者の追加             |
| wiki         | 集計、監査ログ、社内文書、問い合わせ             | 機能フラグ、wiki を使える人              |
| 司令塔アプリ | 手元のタスク、エージェントとの対話ログ           | タスクの作成・更新、エージェントへの指示 |
