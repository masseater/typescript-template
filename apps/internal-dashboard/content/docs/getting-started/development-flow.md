この文書では、このテンプレートを用いて開発を進める際の標準的な開発サイクルと検証の進め方を説明します。

## 開発の原則

- **AI との協調**: コード変更、テスト実行、ブラウザ操作による画面確認、実ログ・トレースの確認は AI エージェントが主体となって自律的に行える構造になっています。
- **main への直接コミット禁止**: 作業は常に独立したブランチまたは worktree を作成して進めます。
- **常に最新の main を同期**: 作業中・push 前・マージ待ちのいかなるタイミングでも、`main` の最新コミットを取り込んでから検証します。
- **全件テストのローカル実行禁止**: PR マージ前の CI ですべての確認が実行されるため、手元では変更の影響範囲に絞った確認を行い、開発の高速性を保ちます。

## 日常の開発サイクル

1. **ブランチの作成**:
   - `main` から作業用のフィーチャーブランチを切ります。
2. **設計・ドキュメントの先行確認**:
   - 仕様や概念の変更を伴う場合は、まず `apps/internal-dashboard/content/docs/` のドキュメント（データモデルや画面仕様）を更新し、意図を明確にします。
3. **実装と局所検証**:
   - 各ワークスペースでコードやテストを編集します。
   - 外部 HTTP 通信は MSW でモックし、DB は実際の SQLite / D1 環境を用いてテストします。
4. **観測と実機検証**:
   - 必要に応じて手元で開発サーバーを起動し、ブラウザ操作（agent-browser 等）やログ・分散トレース（Workers Observability / Local Explorer）で動作を確認します。
5. **コードレビューの実施**:
   - 実装完了後は `.claude/skills/reviews/SKILL.md` の観点（コロケーション、サイレントフォールバック防止、設定クリーンアップ等）に沿ってセルフレビューを行います。
6. **PR の作成とマージ**:
   - コミット・push 後に PR を作成します。
   - PR に `ready-to-merge` ラベルを付与して Mergify のマージキューに入れ、CI による自動検証を経て `main` へ統合します。
