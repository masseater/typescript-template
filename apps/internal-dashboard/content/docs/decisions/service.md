テンプレートを使い始めたら、各節の説明を決めた内容に書き換えます。いつ決めるかは [場面ごとにやること](/checklists) の各ページにあります。

## 目的と利用者

誰の、何の困りごとを、どう解き、どう収益にするかを数行で書きます。案の段階の検討は [GitHub の issue](https://docs.github.com/ja/issues) で進め、やると決めた時点で結論をここに移します。

## 決める人と関係者

- 決める人を 1 人書きます。範囲、期限、予算、公開の承認はこの人が決めます。
- 関係者を役割ごとに書きます。個人の電話番号やメールアドレスはここに書かず、連絡の手段だけを書きます。
- 誰に、何を、どの頻度で報告するかを書きます。

## 性質と規模

利用者数、データ量、書き込みの頻度と同時に来る量、伸び方の見込み、扱うデータの性質（個人情報、決済など）を書きます。DB と決済代行業者の判断は、ここに書いた規模を前提にします。判断の分かれ目は [使い始める手順](/getting-started/first-steps) の 4. と 5. にあります。

## 最初の公開の範囲

入れるものと入れないものを書きます。入れるものは [データモデル](/data-model/overview) と [ページ構成](/pages/internal-dashboard-layout) に反映します。

## 受け入れの条件

何が満たされたら公開してよいかを書きます。公開の前に、決める人がこの条件で承認します。

## 品質の定義

機能ごとに、良い状態と、それを何で測るかを書きます。測り方は [SLI と SLO](/observability/sli-slo) に合わせます。

## 公開日と節目

公開日を書きます。そこから逆算した節目は [GitHub の milestone](https://docs.github.com/ja/issues/using-labels-and-milestones-to-track-work/about-milestones) にします。

## 予算

固定費と変動費の見積もり、月の予算と予備費、赤字を続けてよい期間を書きます。月の予算の金額は GitHub Environment の secret にも入れ、予算監視が [Cloudflare](https://www.cloudflare.com/) の費用と比べます。入れるキーは [使い始める手順](/getting-started/first-steps) の 3. にあります。
