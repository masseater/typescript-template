title: 事業の決めごと
description: 法令、料金、計測、アカウント、企業への販売について決めたことを書き残すページ
---

コードの外側で決めたことを書きます。何を決めるかは [ビジネス面のチェックリスト](/getting-started/business-checklist) に並べてあり、各項目から書き込む節へリンクしています。値がコードや外部サービスの設定にあるものは、値を写さずに置き場だけを書きます。

## 法令と届出

- 法令ごとに、当たるかどうかの判断とその根拠を書きます。確かめた相手（公式の資料、専門家）も書きます。
- 届出や許可を出したものは、番号、日付、更新の期限を書きます。期限は [GitHub の milestone](https://docs.github.com/ja/issues/using-labels-and-milestones-to-track-work/about-milestones) にも入れます。
- 特定商取引法に基づく表記に出す事業者名、所在地、電話番号、返品の条件を書きます。テンプレートには表記のページがありません。有料で売ると決めたら [ページ構成](/pages/internal-dashboard-layout) にページを足します。
- 利用規約とプライバシーポリシーの本文は [管理者アプリの規約](/pages/admin-terms) で版として公開します。プライバシーポリシーに載せる項目は [プライバシーポリシー](/pages/member-privacy) にあります。

## 料金と請求

- 料金、課金の周期、無料期間の値はコードにあります。
  - 価格と周期: `infra/cloudflare/src/features/cloudflare/billing.ts`
  - 無料期間と税の自動計算: `libs/config/src/features/config/billing.ts`
- 支払いに失敗したときの再試行と督促のメールは [Stripe のダッシュボード](https://dashboard.stripe.com/) の Revenue recovery の設定で決めます。決めた回数と間隔をここに書きます。
- 返金するかどうかと、返金を誰が決めるかを書きます。
- クーポンと、プランを変えたときの日割りの扱いを書きます。
- 領収書と請求書を誰がどこから出すかを書きます。電子で受け取った請求書と出した領収書を保存する場所も書きます。

## 計測と集客

- KPI ごとに、定義、計算に使うデータ、見る場所、見る人を書きます。
- 流入元を記録する URL のパラメータ（UTM）の付け方を書きます。
- 入れている計測と広告のタグを、送信先、送る情報、目的と一緒に並べます。外部送信規律で公表する内容はこの一覧と同じなので、プライバシーポリシーの版にもそのまま載せます。
- [Google Analytics](https://marketingplatform.google.com/about/analytics/) の測定 ID は GitHub Environment の secret に入れます。キーは [使い始める手順](/getting-started/first-steps) の 3. にあります。

## ドメインとアカウント

- ドメイン、類似ドメイン、SNS のアカウント名、商標を、取った日と更新の期限と一緒に書きます。
- 契約している外部サービスを、用途、契約の名義、支払い手段、管理する人、解約の手順と一緒に並べます。クラウドのリソースは [Alchemy](https://v2.alchemy.run/) の宣言（`infra/cloudflare` と `infra/github`）がそのまま一覧になります。ここにはアカウントと契約だけを書きます。

## 企業に売る条件

- インボイスの登録番号と、請求書を出す手段を書きます。
- 稼働率の約束（SLA）と、下回ったときの返金を書きます。
- 解約したときのデータの返却と削除の手順を書きます。
- 取った認証と、その更新の期限を書きます。セキュリティのチェックシートへの回答は、次の顧客にも使えるようにここからリンクします。
