# Lint ルールの無効化レビュー

対象となる変更に含まれる lint ルールの無効化をすべて確認する。

各無効化について、以下を行う。

1. その lint ルールが何を防いでいるか確認する。
2. 現在のコードや設定に対して、その無効化が本当に必要か確認する。
3. 不要であれば無効化を削除し、根本原因となっているコードや設定を修正する。
4. lint ルールを弱めるのではなく、コードや設定を変更して lint ルールを満たすことを優先する。
5. 修正後、関連する lint チェックを実行して確認する。
6. 本当に必要な場合のみ無効化を残す。その場合、そのコードや設定に固有の具体的な理由があることを確認する。

以下をレビュー対象とする。

- `eslint-disable`、`eslint-disable-next-line` などのインライン無効化
- ファイル単位の lint 無効化
- lint 設定ファイルでのルールの override
- 複数のルールやルールカテゴリ全体を対象とした広範な無効化
- 既存の lint ルールを弱める設定変更

以下は、無効化を正当化する理由として認めない。

- 修正のために既存コードを変更する必要がある
- コード自体は現在正常に動作している
- lint ルールによってコードが冗長になる
- lint ルールが不便である
- 既存コードが以前から存在している
- 無効化を削除するとリファクタリングが必要になる

lint ルールを満たすことが、意図した実装や必要な設定上の制約と明確に両立しない場合は、無効化を残してよい。

無効化を残す場合は、以下の優先順位で最も狭い範囲の無効化を使用する。

1. `disable-next-line` など、対象箇所だけを無効化する方法
2. 特定のコードブロックだけを無効化する方法
3. ファイル全体の無効化
4. lint 設定によるルール全体の無効化

特に、単一の行についてのみ lint ルールを無効化する必要がある場合は、`disable-next-line` を使用する。ファイル全体や広範囲を無効化する方法で代替してはならない。

無効化を残す場合は、なぜその箇所では lint ルールを満たせないのかが分かる具体的な理由を確認する。

修正に必要な作業量は、無効化が必要かどうかを判断する基準にしない。

不要な無効化を発見した場合は、指摘だけで終わらせず、無効化を削除して問題を修正し、lint が通ることを確認する。
