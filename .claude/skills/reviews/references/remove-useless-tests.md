---
name: remove-useless-tests
description: 無意味なテストを見つけて削除する。
---

## 基準

**現在の実装ではなく、維持したい仕様・振る舞い・制約をテストする。**

- 削除した機能・実装・概念が存在しないことを確認するだけのテストは削除する。
- 「削除したものが再び追加されないようにする」という理由だけではテストを残さない。
- 不在そのものが明示的な仕様・制約である場合を除き、不在を検証するテストを追加しない。
- テストのためだけに、存在しないことを保証する新たな概念や制約を増やさない。
- 実装詳細の存在・不在を固定するだけのテストは削除する。
- 変更によって不要になったfixture、mock、helperも削除する。

例えば、次のようにコマンドの具体的な内容を固定するテストは書かない。

```ts
expect(effectDiagnostics["check:effect"].command).toBe(
  "\"$(effect-tsgo get-exe-path)\" --pretty false --noEmit -p tsconfig.json && ...",
);
```

これは `check:effect` が必要な検証を行うことではなく、現在のコマンドの書き方を固定している。

代わりに、外部から見える契約や維持すべき依存関係をテストする。

```ts
expect(appRun.tasks.build.dependsOn).toEqual(
  expect.arrayContaining(["check:effect"]),
);
```

## 判断

**そのテストが失敗したとき、どの仕様・振る舞い・制約が壊れたのか説明できるか確認する。**

「現在こう書かれている」「現在こう構成されている」しか説明できないなら、そのテストは不要。

ただし、互換性・不変条件・意図的な禁止事項など、**その状態を維持すること自体が仕様である場合はテストする。**

カバレッジ不足だけを理由に、実装詳細を固定するテストを追加しない。
