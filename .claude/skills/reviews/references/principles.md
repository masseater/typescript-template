# 中核原則

どの対象を触っていても当たる判断。主題別の基準に優先する。実装の速さ、差分の小ささ、既存との見た目の一致は、これらを緩める理由にならない。

## 重複と持ち主

- Oxlint と knip が挙げた一致は候補として扱う。挙げたこと自体を統合の根拠にせず、挙げないことを重複が無い証拠にしない。
- 一致を外すためだけの書き換えや、両方を残したままの抑制で報告を消さない。
- 報告と実態が食い違うと考えるなら、理由を突き止めてから `knip.ts` に例外を書く。
- 重複と呼ぶのは、同じ責務を負う宣言が 2 か所以上にあり、どれも他を取り込んでいない状態だけ。字面の一致だけで重複と呼ばない。
- 責務と契約の一致を確かめられないもの、今後別々に変わる見込みのものは分けたまま残す。迷ったら重複を残す側に倒す。
- 統合後の持ち主に責務を言い当てた狭い名前を付けられないなら、それは 2 つの責務。
- 持ち主は、その責務を既に負っている workspace に置く。依存の向きを逆にしてまで寄せない。無ければ狭い名前の持ち主を新しく作る。
- 複数の workspace が要り、どれにも属さない宣言は、双方が依存できる中立の置き場所に置き、その置き場所が何を断るかを決める。
- 持ち主を迂回する書き方が機械的に検出できるなら、同じ変更でガードを入れる。

## 意図を所有する文書

- 文書化された意図・ふるまい・不変条件を変える変更は、それを所有する文書を同じ変更の中で実装より先に更新する。無ければ作る。
- 古いふるまいを説明したままの文書を残さない。

## ずれうる設計を採らない

- 2 つの記述が同じ事実かは、片方を変えたときにもう片方が失敗するかで決める。
- 別々の理由で変わりうるものを、形が似ているという理由で 1 つに寄せない。
- 同じ事実の二重表現には権威を 1 つ選び、残りを導出する。導出できないなら、ずれた時点で機械的に落ちる形にする。導出も検出もできない設計を採らない。
- 不正な組み合わせを「書かない」約束で防がない。表現できない形にするか、機械的に弾く。
- 外部サービスの設定値は Alchemy の宣言に置き、ずれは `alchemy plan` に見つけさせる。

## 確認が保証している範囲

- 確認が通ったことを、その確認が見ていない性質の保証にしない。
- 失敗を返す形で動いている確認と同じ違反を、レビューで重ねて数えない。報告だけで終了コードを動かさない確認は、動いているとみなさない。
- 確認が届かない側の判断を省かない。届かないのは、実装と文書のずれ、型の契約と実行時の契約のずれ、宣言と外の状態のずれ、2 つの側が出会う場所だけに現れる食い違い。

## 始めたことを閉じきる

- 統合の完了は、責務を負う宣言が 1 つ残り、すべての利用箇所がそこへ届き、迂回が塞がれた時点。見つけた独立の宣言は同じ変更で全部消す。
- 不正な構造の上に回避策を足さない。
- ファイルを変えるときは、そのファイル全体と、公開している型・所有文書・呼び出し側の前提を読む。該当行の周辺だけを見て直さない。
- ある書き方を禁じたら、その変更の中の同型の箇所を残らず直す。

## 自動化が所有する出力

- 触る出力を所有する自動化があるなら、先に実行して出力を全部読む。終了コードだけで通ったとみなさない。
- 自動化が対応していないことを、不変条件を外す理由にしない。

## 同時に切り替えられない解釈者がいる契約

state store の宣言と state、デプロイ先の設定、env を復号する鍵、Alchemy の stack 間で受け渡す出力がこれにあたる。手元から先に適用すると state だけが進み、次に main から plan した者の apply が落ちる。

- 独立に更新される解釈者がいなければ契約として扱わなくてよい。同じソースツリーにあっても原子的に切り替えられないなら契約として扱う。
- 相手が同時に追随する前提を置かない。
- 移行の全期間、どの解釈者からも契約が解釈できる状態を保つ。順序、経由する中間状態、旧解釈を落とす時点を同じ変更で決める。
- 旧解釈は、すべての解釈者が移り終えたことを確かめてから落とす。
- 書き出した導出結果の作り方を変えるときは、古い作り方の結果が読み捨てられる形にする。

## 優先順位

1. 責務の境界を守ることが、字面の一致をなくすことに優先する。
2. ずれうる設計を採らないことが、速さ・差分の小ささ・見た目の一貫性に優先する。
3. 条件を閉じきることと統合を終わらせることが、変更を小さく保つことに優先する。
4. 自動化が所有する変換を実行することが、手で編集することに優先する。
5. すべての解釈者が契約を解釈できることが、最終形への最短到達に優先する。移行境界を決めて並存を有限に区切っているなら 2 に反しない。
