# コードを簡素にする

## 範囲

- コードだけでなく、各 workspace の設定やタスク構成にも当てる。
- 簡素にする書き換えでは振る舞いを変えない。入出力、失敗のしかた、副作用の順序はそのまま残し、書き方だけを変える。
- 変更で複雑さが減るか、既存の仕組みで置き換えられないかを確かめる。

## 書き方

- 型で表現できる安全性を、実装時の分岐や手動チェックで代替しない。複雑な `if` / `switch` を増やさず、バリデーションライブラリや型で表現する。
- 場当たり的な修正で複雑さを増やさない。必要なら設計、責務、データ構造から変える。
- 後方互換性のためだけの分岐、ラッパー、旧 API を残さない。
- ファイルパスや正規表現による不安定なマッチングではなく、バリデーションライブラリで対象を識別する。
- 引数の受け渡しや一部の値の抽出だけを目的にした関数、型、インターフェースを増やさない。
- 行数を減らすために式を 1 行へ詰め込まない。途中の値に名前を付けて、上から順に追える形にする。

## 無駄な処理

- 同じ計算や同じ I/O を 1 つの処理の中で繰り返さない。1 回目の結果を使い回す。
- 互いの結果を使わない処理を 1 つずつ待たない。まとめて並行に動かす。
- 起動時やリクエストのたびに動くコードに、待ちの発生する処理を足さない。
- 長く保持する関数やオブジェクトに、大きな値を持つ外側のスコープを閉じ込めない。必要な値だけを取り出して渡す。

## workspace とタスク

- workspace 固有の export、コマンド、設定を必要以上に増やさない。リポジトリ全体で扱う処理はルートに集約する。workspace の設定は共通設定を継承し、固有の設定は最小にする。
- 手動実行を前提にした独自スクリプトを増やさず、起動、終了、ビルドなどのライフサイクルに組み込む。個別のチェックタスクを列挙して実行せず、lifecycle の集約を使う。
- `node` で直接ファイルを実行せず、[Vite+](https://viteplus.dev/) の `vp` のタスクランナーに乗せる。
