# シンプルに実装する

コードだけでなく、各 workspace の設定・タスク構成まで見る。

- 型で表現できる安全性を、実装時の分岐や手動チェックで代替しない。複雑な `if` / `switch` を増やさず、バリデーションライブラリや型で表現する。
- 既存のライブラリ・フレームワーク・リポジトリの仕組みを優先し、自前実装を増やさない。ユーティリティは `es-toolkit`。
- 場当たり的な修正で複雑さを増やさず、必要なら設計・責務・データ構造から変える。
- 後方互換性のためだけの分岐・ラッパー・旧 API を残さない。
- ファイルパスや正規表現による脆弱なマッチングではなく、バリデーションライブラリで対象を識別する。
- 引数の受け渡しや一部の値の抽出だけを目的とした関数・型・インターフェースを増やさない。
- workspace 固有の export・コマンド・設定を必要以上に増やさない。リポジトリ全体で扱う処理はルートに集約する。workspace の設定は共通設定を継承し、固有設定は最小にする。
- 手動実行を前提とする独自スクリプトを増やさず、起動・終了・ビルドなどのライフサイクルに組み込む。個別の確認タスクを列挙して実行せず、lifecycle の集約を使う。
- `node` で直接ファイルを実行せず、`vp` のタスクランナーに乗せる。
- 変更で複雑さが減るか、既存の仕組みで置き換えられないかを確認する。
