# 境界と型

ここに書くのは lint が判定できないものだけ。

## 外部 I/O とその境界

外部 I/O は、値がこのリポジトリのロジックの外側で決まる入出力。それ以外の依存はプロセス内の決定的な振る舞いとして扱う。

- ロジックから外部 I/O を直接呼ばない。このリポジトリが所有する注入境界を経由する。
- 注入境界は、外部 I/O の位置にあるか、テストではない呼び出しが今あるときだけ足す。
- 外部 I/O の注入境界は、向こう側を差し替えたときにこちらの分岐を全部通せる大きさに保つ。
- 存在が任意のパスは読む前に不在を判定する。読み取りの失敗をすべて不在として扱わない。
- 存在が任意のディレクトリの下に書くときは、書く前にディレクトリを用意する。
- 環境変数は `libs/config` の型付きの `env` を経由する。`process.env` を直接参照しない。

## 外から入った値

- 外から来た値は、入ってくる境界で内側の型に移す。使う場所ごとに形を確かめない。
- 境界で形が合わなければ失敗にする。
- 1 つの判定を 2 つの概念に使わない。今構造が一致していても概念ごとに判定を定義する。
- 判定を通った形の静的型と、フィールドの意味は、判定の定義から導出する。
- 省略可能にするフィールドには、実際に欠ける場面を挙げる。挙げられないなら必須にする。文脈ごとに形が変わるなら文脈を決める値を先に読み、全文脈を 1 つの判定に畳まない。
- 判定を書く手段は Effect Schema の 1 つに保つ。その外で条件を並べた確認を書かない。

## 型が言えること

- その場で使える中で最も精密で健全な型を保つ。不正な状態は型で表現不能にし、呼び出し側の規律に頼らない。
- 引数と戻り値の契約はシグネチャを唯一の出所とし、外で要る型はそこから導出する。構造だけ同じ型を並行させない。
- 型チェックが導けない型として扱うときは、値を実際に確かめる確認を同じ境界に置き、通った値だけを主張の対象にする。中身が値を見ないアサーション・型述語・表明で拒否を消さない。
- 実行時のモジュールとして取り込む依存は、モジュール形式が消費側と噛み合うことを確かめる。型解決が通ったことを実行時に読める証拠にしない。

## 判断が割れたとき

- 決められないときは後から戻せる側へ倒す。検証を足す、注入境界を足さない、省略可能にせず必須にする。
