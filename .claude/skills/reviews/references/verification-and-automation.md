# 検証と自動化

## ガードが落ちることを確かめる

- ガードを足したら、違反を仕込んだ入力でレポートが出ること、違反でない入力で出ないことを確かめる。設定に存在することを、検出できている証拠にしない。
- ガードをすり抜けた違反を見つけたら、コードを直し、落ちるべき入力にその抜け道を足す。
- レポートには、破られた不変条件と直す方向の両方を含める。
- 自動修正を用意するのは、安全で決定的な直し方がちょうど 1 つに定まるときだけ。自動修正が安全に終えられない部分は、失敗するガードとして残す。
- 以下の順番で仕組みを構築できないかを検討する。
  - oxlint ルール -> dont-review-it の check コマンド -> 独自パッケージ -> CI 限定スクリプト

## lint の無効化は 1 行に留める

- lint の指摘は、まず指摘されたコードか指摘を生んだ条件を直す。
- どうしても残す行は、`oxlint-disable-next-line <規則名> -- <理由>` をその行の直前に書き、規則名と理由を必ず添える。
- ファイル単位、パッケージ単位、範囲指定での無効化はしない。lint 設定でファイルやパッケージを指定して規則を切ることもしない。
