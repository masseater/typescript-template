# 観測性

監視が運ぶ未解決の記録を、いま直すべきものの一覧と一致させる。秘密と個人を特定できる値を出力から落とす判断を先に当てる。

## 監視へ送る対象

- 送るのは、こちらの変更で挙動が変わる不具合だけ。入力の不備、存在しない URL、対応していないプロトコルの版、認証の失敗など仕様どおりの応答を不具合として計上しない。
- 仕様どおりの拒否が監視に届いているなら、送らないように直す。監視側で表示から外して済ませない。送った時点で quota を消費している。
- 送るかどうかを状態コードで判定しているなら、状態コードを持たない失敗（認証の失敗、DB ドライバの例外）がすり抜ける前提で、種別ごとに判定へ乗せる方法を決める。
- 外部サービスの失敗は、こちらの応答をどうするかを先に決め、それに従って送るかを決める。外部の失敗であることを理由に自動的に外さない。

## 応答の状態コード

意味は RFC 9110、場面ごとの選択は Google の `google.rpc.Code` の分類と HTTP への対応に従う。本体は RFC 9457 の Problem Details（`application/problem+json`）。使いたいコードが `@repo/config` の `httpStatus`（失敗側は `@repo/runtime` の `FailureStatus`）に無ければ型に足してから使う。

- 資源が存在しない: 404。見つからなかった値を描画へ渡して 500 にしない。
- 資格が無い、または無効: 401。
- 権限が無い: 存在を調べる前に権限を判定して 403。存在自体を伏せる必要を説明できるときだけ 404。
- 引数が状態に関わらず不正: 400（`INVALID_ARGUMENT`）。引数は正しいが状態が実行できない: 400（`FAILED_PRECONDITION`）。範囲外: 400（`OUT_OF_RANGE`）。
- 既に存在する、または並行操作と競合: 409。割り当てを使い切った: 429。未実装か無効化: 501。
- 外部サービスが使えない: 503、復帰の見込みが分かれば `Retry-After`。時間内に応答しない: 504。
- 502 を返さない。外部 API を呼んで失敗したアプリは中継ではない。
- どの 5xx も当てはまらないときだけ 500。既定の選択肢にしない。
- 外部サービスが失敗しても、欠けた部分を除けば応答の目的を達せられるなら成功として返し、欠けたことを `WARNING` で記録する。5xx で応答ごと落とさない。達せられないなら 503 か 504 を返して監視へ送る。
- 状態コードを決める箇所は境界の 1 つに保ち、同じ失敗に出どころごとに違うコードを割り当てない。

## 送った記録を閉じる

- 監視の判定状態を「直った」へ進めるのは、修正か送信を止める変更が実稼働に届いたことを確かめてから。通知を減らすためだけに動かさない。
- 直さないと決めたものは、送らないように直したうえで閉じる。送り続けたまま通知だけ止めない。
- 未解決のまま残っている記録は、直すと決めたものとして扱う。

## アラート

- アラートは Alchemy の宣言と `infra/*-monitor`・`libs/monitor` に書く。Cloudflare の管理画面だけで作らない。
- 宛先と判定条件を宣言した状態で有効にする。宛先は担当者が普段見ている場所。宛先の無い有効なアラートを残さない。
- 対象は production に限る。他の環境の事象を通知に載せない。
- 繰り返し発火しうる事象には再通知の間隔を決める。
- 動いているかの監視は、落ちたことが通知へ届くところまで用意する。

## 記録の流れ

- 発生源の種別ごとに流す先を 1 つ決める。1 つの発生源を複数の先へ重複して流さない。既に複数へ流れていれば一本に寄せる。中継するためだけの中間処理を残さない。
- 本番の記録はそのランタイム向けの構造化の境界を通す。呼び出し側で logger を作り直したり、サービス名・環境・送り先を上書きしたりしない。本番で動くコードの出口に素の `console` を置かない。

## 深刻さ

- 必要な資源・依存・設定値・必須の入力の欠落: `WARNING` 以上。
- 外部の依存の失敗: `ERROR`。どの依存かを構造化した欄に残す。
- 入力の不正・業務規則の違反・状態の衝突: `WARNING`。
- 対象が存在しない、権限が無い: `INFO`。
- 分類できない失敗は上位へ渡し、そこで `ERROR` として記録させる。
- 代替値で続行した置換: `WARNING` 以上。

## 記録に何を残すか

- 捕まえた失敗は、失敗そのものと `cause` の連なりを残す。文言だけ写して元を落とさない。
- 識別子・処理の段階・引数は、秘密の値を落としたうえで構造化した欄に載せる。文言は固定し、変わる値は欄に置く。
- 出力先の容量に収まらないなら、出力先を分けるか構造化した欄へ移す。削って残りを捨てない。どうしても落とすなら、落とした事実を記録に残し、在り処は読み手に開示が許された場所だけを指す。
- 秘密を落とした後の形を出してよい内容の全体として扱う。落とす前の複製を残さない。
