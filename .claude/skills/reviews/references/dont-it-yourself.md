# 自前で作らない

## 既製のものを探してから書く

- ライブラリ、フレームワーク、ランタイム、リポジトリの仕組みにある処理を自前で実装しない。既製のものに載せて、メンテナンスするコードを減らす。
- 一般に定義された基準（RFC、W3C、ECMA、ISO、業界標準、広く使われる形式や規約）に沿った処理は、その基準を実装したライブラリがあるものとして探す。基準の名前と番号、形式の名前、扱うデータの名前で npm を検索し、メンテナンスが続いていること、型定義があること、依存が少ないことを確かめる。
- 次のものを自前で書かない。UUID や ULID の生成。日付・時刻・期間の解析と整形。semver の比較。深い等価比較、deep merge、`groupBy`、`chunk`、`debounce` などのユーティリティ（`es-toolkit` を使う）。retry と backoff。cron 式の解析。CSV、TOML、YAML、INI、`.env` の解析。URL、メールアドレス、電話番号、IBAN の検証。エスケープと sanitize（HTML、shell、SQL、正規表現）。base64、hex、hash、署名、暗号。glob と path のマッチ。CLI の引数解析。ロック、mutex、キュー、rate limit。テンプレートエンジンと Markdown の変換。
- 既製の関数を包み直すだけのラッパーを作らない。
- 既製のものが要件の一部しか満たさないときは、足りない部分だけを書き、満たす部分を書き直さない。拡張する口があるなら、そこから足す。

## 自前のまま残してよいもの

- 探した記録（検索した名前と見た候補）を同じ変更に残せるときだけ、自前で書いてよい。
- 既製のものを使えないと決めるときは、要件のどこが満たされないか、拡張の口がないこと、代替のライブラリも当たらないことを示す。「軽い」「簡単」「依存を増やしたくない」「数行で済む」は理由にしない。
- 残した自前の実装は、レビューのたびに置き換えられる既製のものがないかを探し直す。
