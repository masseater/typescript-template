description: コロケーションの観点から変更をレビューし、関連性・所有関係・変更単位に基づいた自然な配置と明確な依存境界を維持する。
---

コードだけでなく、設定・テスト・ドキュメント・その他の関連ファイルまで含めて、実際の利用場所と構造を確認する。

## 基準

- 同じ feature・責務に属するものを近くに置く。
- 一緒に変更・理解されるものを近くに置く。
- feature 固有のコード・型・utility・定数・hook・テスト・設定・ドキュメントを、その feature にコロケーションする。
- `shared` / `common` / グローバルな場所には、本当に複数箇所から共有されるものだけを置く。
- 将来使うかもしれないという理由で、共有・抽象化・分離しない。
- パッケージは、実際に再利用する境界として必要な場合のみ分離する。
- feature / package の境界を明確にし、境界の外から内部実装を直接利用しない。
- ImportLint で package 内部への直接 import を防ぎ、dependency-cruiser で package / feature 間の依存方向を制約する。
- 境界を守るために lint の無効化や個別の例外を追加しない。
- 既存のリポジトリの構成・命名・境界を優先する。既存の構造に合わせて配置する。

## 判断

**そのファイルやコードを変更するとき、何と一緒に変更・理解・所有するものかを基準に配置する。**

複数箇所から使われないものを共有領域へ出さない。分離しただけで再利用性が増えないものを package 化しない。
