# コロケーション

`apps` / `libs` / `infra` の区分の内側の配置。

- 同じ feature・責務に属するもの、一緒に変更・理解されるものを近くに置く。feature 固有のコード・型・utility・定数・hook・テスト・設定はその feature にコロケーションする。
- `shared` / `common` / グローバルには、実際に複数箇所から共有されるものだけを置く。将来使うかもしれないという理由で共有・抽象化・分離しない。
- package は実際に再利用する境界として必要な場合だけ分ける。分離しても再利用性が増えないものを package 化しない。
- feature / package の境界の外から内部実装を直接使わない。依存の向きは `tools/dont-review-it` の `dependency-cruiser.ts` が制約する。境界を守るために lint の無効化や個別の例外を足さない。
- 既存の構成・命名・境界に合わせて置く。
