# 過度な共通化を禁ずる

## 共通化する時機

- 関数・型・hook・コンポーネント・基底クラスは、同じ目的で使う 2 つ目の呼び出し元が今あるときに共通化する。

## 次のどれかに当たる共通の側は解く

- 値が呼び出し元の名前や用途に対応する引数がある（`isAdmin`、`fromCheckout`、`type: "invoice" | "receipt"`、特定の呼び出し元だけが渡すオプション）。
- 特定の呼び出し元のためだけの分岐や早期 return がある。
- 1 つの呼び出し元の要件で共通の側を変えると、他の呼び出し元の振る舞いやテストが変わる。
- 一部の呼び出し元だけが使う処理がある。
- テストが、どの呼び出し元も使わない引数の組み合わせを検証している。

## 解き方

- 中身を各呼び出し元へ戻し、その呼び出し元が通らない枝と使わない引数を消す。そのうえで目的が同じものだけを寄せ直す。
- 共通の側にだけあったテストを、各呼び出し元の観測できる振る舞いのテストに移す。
- 引数・オプション・分岐を足して、合わない呼び出し元を共通の側に収めない。
- 継承を処理の使い回しに使わない。
