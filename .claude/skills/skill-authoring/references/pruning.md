# 既存の skill や AGENTS.md を削る

## 手順

1. 対象を 1 つの skill か 1 つの AGENTS.md に絞る。全文を読んで、SKILL.md の基準に反する文と、下の「候補にする文」に当たる文を候補として一覧にする。
2. lint・型・テストで検出できる候補は、先にチェックを実装してから文を消す。
3. 残りの候補ごとに、その文がないと結果が変わりそうな依頼を、このリポジトリの直近の commit と PR から 2〜3 件作る。
4. worktree を 2 つ作り、片方は候補の文を残した版、もう片方は消した版にする。
5. 同じ依頼を両方の worktree で `claude -p` に 3 回ずつ渡し、下の「判定」で消すかを決める。
6. 1 回の変更で消すのは 1 つの節までにする。skill 全体を LLM に要約させたり書き直させたりしない。
7. 消した文、試した依頼、両方の版の結果を commit ログに書く。

返答には、消した文の数と行数の変化、残した候補とその判定結果、追加したチェックを書く。

## 候補にする文

- モデルが指示なしでも同じ行動を取る文。一般的なベストプラクティス、ツールやライブラリの基本的な使い方、公式ドキュメントに書いてあること。
- 同じ判断を別の言い回しで繰り返す文。skill の中、他の skill、AGENTS.md のどこか 1 か所に残し、他を候補にする。
- 前置き、要約、見出しを言い換えただけの文。
- 一度だけ起きた失敗を一般化した規則。まだ起きていない失敗に備える規則。
- 古いバージョンの API やモデルに合わせた指示。
- 「必ず」「絶対に」、大文字の MUST のように、強調だけで守らせようとする言い回し。強調を外した文を候補にする。
- 候補を選ぶために作ったどの依頼でも読まれない reference。

## 候補にしない文

- コードや設定を読んでも分からない、このリポジトリ固有の決定。
- モデルの既定と違う行動を求める文。
- 望む形を示す具体例。
- 秘密情報、権限、取り返しのつかない操作に関わる文。検証で差が出なくても残す。

## 判定

- 消した版の 3 回がすべて、残した版と同じ結果なら消す。1 回でも悪くなったら残す。
- 比べるのは結果の行動（変更したファイル、実行したコマンド、返答の中の判断）。文面の一致では比べない。
- 依頼の文に候補の文の内容を書かない。
- 残した版でも期待する行動が出ない文は、守られていない文として扱う。lint・型・テストに移せるなら移し、移せないなら消す。
- 結果は違うが良し悪しを決められないときは、依頼を増やして 3 回ずつやり直す。それでも決められなければ残す。
- description を削るときは、その skill を呼ぶべき依頼と呼ぶべきでない依頼を 5 件ずつ作り、どちらの版でも起動の有無が同じであることを確かめる。
